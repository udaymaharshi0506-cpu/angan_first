6. CRITICAL SECURITY, PRIVACY & AUTHENTICATION VULNERABILITIES
================================================================================

Vulnerability 1: Weak JWT Secret Fallback (High Severity)
- Location: `src/lib/auth.ts:15`
- Code:
  `const secret = new TextEncoder().encode(process.env.AUTH_SECRET || createHash("sha256").update(process.env.DATABASE_URL || "local-preview-session").digest("hex"));`
- Risk: If `AUTH_SECRET` is not provided in environment variables, the system derives the signature key from `DATABASE_URL` or the static string `"local-preview-session"`. Anyone who knows or guesses the database connection string or default fallback can forge valid JWT access tokens for ANY user ID, including administrators.
- Fix: Throw an explicit fatal error at application startup if `AUTH_SECRET` is missing in production.

Vulnerability 2: Production Bypass via Demo Mode Detection (High Severity)
- Location: `src/lib/seed.ts:13` and `src/lib/api-handler.ts:105, 121, 134, 159`
- Code:
  `export const demoMode = () => (process.env.DEMO_MODE === "true" || (process.env.DEMO_MODE !== "false" && /(?:127\.0\.0\.1|localhost)/.test(process.env.DATABASE_URL || ""))) && !process.env.TWILIO_VERIFY_SERVICE_SID;`
- Risk: If a staging or production container connects to a local database proxy (e.g., Cloud SQL Proxy, pgbouncer, or container network on 127.0.0.1) and Twilio SID is omitted, `demoMode()` automatically evaluates to `true`.
  When demoMode is active:
  1. Phone OTP verification accepts the static code `"123456"`.
  2. Admin Two-Factor Authentication (2FA) accepts `"000000"` (`src/lib/auth.ts:134`).
  3. Anyone can sign in as administrator by entering the demo credentials and "000000".
- Fix: Enforce `DEMO_MODE=true` explicitly; never infer demo privileges from connection string hostnames.

Vulnerability 3: Local Ephemeral Storage for Image Uploads (Medium-High Severity)
- Location: `src/lib/api-handler.ts:358-362`
- Code:
  `const folder = path.join(process.cwd(), "public", "uploads");`
  `await writeFile(path.join(folder, filename), bytes);`
- Risk: In modern cloud deployments (Vercel, AWS Fargate, Google Cloud Run, Kubernetes), the local filesystem is ephemeral and read-only.
  1. Uploaded property photos will be wiped upon instance restart or deployment.
  2. Requests routed across different server instances will receive HTTP 404 for uploaded files.
  3. No magic-number inspection is performed on uploaded image files (only file extension and client-supplied MIME type), allowing malicious arbitrary file uploads.
- Fix: Use S3 / Cloudinary / R2 object storage with binary signature verification.

Vulnerability 4: Buffer Length Crash in `timingSafeEqual` (Medium Severity)
- Location: `src/lib/auth.ts:145`
- Code:
  `if (timingSafeEqual(expected, Buffer.from(code))) return true;`
- Risk: Node.js `crypto.timingSafeEqual(a, b)` requires that `a.length === b.length`. If an input reaches this check where `code` has a different byte length than `expected` (6 bytes), Node.js throws an unhandled `RangeError: Input buffers must have the same length`, crashing the request handler and resulting in an unexpected 500 error instead of a clean 401.

Vulnerability 5: Incomplete Cascade Deletion Constraints (Medium Severity)
- Location: `src/db/schema.ts:68, 94, 104`
- Detail:
  `scheduledByAdminId: uuid("scheduled_by_admin_id").notNull().references(() => users.id)`
  `adminId: uuid("admin_id").notNull().references(() => users.id)`
  Unlike customer and owner foreign keys which have `{ onDelete: "cascade" }`, admin references lack cascade rules or `onDelete: "set null"`. If an admin user is deleted, PostgreSQL blocks the operation or aborts with a foreign key constraint violation.

7. RUNTIME BUGS, BROKEN COMPONENTS & EDGE CASE FAILURES
================================================================================

Bug 1: Empty Photo Gallery Causes NaN Crash in PropertyDetail
- Location: `src/components/property-detail.tsx:57, 67`
- Code:
  `const photos = property.images.length ? property.images : [];`
  `{[1,2].map((index) => <button onClick={() => setPhotoIndex(index % photos.length)} ...>`
  `onClick={() => setPhotoIndex((photoIndex - 1 + photos.length) % photos.length)}`
- Failure: If a property has no images (`property.images = []`), `photos.length` is 0.
  - `index % 0` produces `NaN`.
  - Clicking gallery arrows or thumbnails sets `photoIndex` to `NaN`.
  - `photos[NaN]` evaluates to `undefined`, breaking image rendering and throwing errors in React.
- Fix: Guard with `if (!photos.length)` and provide a fallback placeholder image.

Bug 2: Invalid UUID Route Parameter Throws Unhandled 500 Database Error
- Location: `src/app/property/[id]/page.tsx:10, 16`
- Code:
  `if (!/^[a-f0-9-]{36}$/i.test(id)) notFound();`
- Failure: The regular expression `/^[a-f0-9-]{36}$/i` matches any 36 characters of hex and hyphens (for example, `"------------------------------------"` or `"123456789012345678901234567890123456"`).
  When this invalid format is passed to `db.select().from(properties).where(eq(properties.id, id))`, PostgreSQL rejects it with:
  `ERROR: invalid input syntax for type uuid`
  Instead of cleanly returning a 404 page via `notFound()`, Next.js throws an unhandled server error (500).
- Fix: Use standard UUID validation: `/^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i` or `z.string().uuid().safeParse(id).success`.

Bug 3: Unsanitized SQL LIKE Wildcards in Search Queries
- Location: `src/lib/queries.ts:40, 41, 46, 47`
- Code:
  `ilike(properties.city, `%${filters.city}%`)`
  `ilike(properties.title, `%${filters.q}%`)`
- Failure: The `%` and `_` characters are not escaped. If a user searches for `50%` or `Villa_1`, PostgreSQL treats `%` as arbitrary string matches and `_` as single character wildcards, returning distorted search results or creating table scan performance bottlenecks.
- Fix: Escape `%` and `_` with backslashes before injecting into `ilike` clauses.

Bug 4: View Count Inflation & Resource Contention
- Location: `src/lib/api-handler.ts:176` and `src/components/property-detail.tsx:30`
- Code:
  `await db.update(properties).set({ views: sql`${properties.views} + 1` }).where(eq(properties.id, property.id));`
- Failure: Every GET request to `/api/properties/:id` and every page visit to `/property/:id` executes an immediate `UPDATE` query on the database.
  1. A scraper or crawler requesting property pages rapidly locks rows in PostgreSQL.
  2. Database read replicas cannot serve property details because every read triggers a write query.
- Fix: Debounce views, store view counters in Redis/in-memory batches, or use dedicated asynchronous analytics events.

Bug 5: Client-Side Hydration FOUC (Theme & Date Mismatch)
- Location: `src/components/providers.tsx:70` and `src/components/site-shell.tsx:55`
- Code:
  `const stored = localStorage.getItem("aangan-theme");`
  `if (stored === "dark") { setTheme("dark"); ... }`
- Failure: The initial HTML rendered by Next.js server uses the default `"light"` theme. Upon hydration, client script checks `localStorage` and triggers `setTheme("dark")`. This results in an unsightly Flash of Unstyled Content (FOUC) and layout shifting on initial load.
- Fix: Inject an inline script in `src/app/layout.tsx` before React hydration to read `localStorage` and set `data-theme` on `<html>`.

8. DATABASE SCHEMA, DRIZZLE ORM & DATA INTEGRITY DEFECTS
================================================================================

1. Redundant Roles Definition:
   - In `src/db/schema.ts`, `users` table defines both:
     `role: varchar("role", { length: 20 }).notNull().default("customer")`
     `roles: jsonb("roles").$type<Array<"customer" | "owner" | "admin">>().notNull().default(["customer"])`
   - In `src/lib/api-handler.ts:309`, role updates modify both fields:
     `roles: input.addOwnerRole ? [...user.roles, "owner"] : user.roles`
     `role: roles.includes("owner") && user.role !== "admin" ? "owner" : user.role`
   - Having two fields representing the same conceptual entity causes data synchronization drifts if directly updated.

2. Drizzle Configuration File Format:
   - `drizzle.config.json` is deprecated in newer Drizzle Kit releases.
   - Recommended replacement: `drizzle.config.ts` using `defineConfig({ ... })`.

3. Missing Transaction Handling in Multi-Step Mutations:
   - In `src/lib/api-handler.ts:229-238` (Lead Creation):
     1. Inserts into `leads`
     2. Inserts into `leadEvents`
     3. Inserts into `notifications` (owner)
     4. Inserts into `notifications` (seeker)
   - These are executed as separate, non-atomic queries without `await db.transaction(async (tx) => { ... })`. If the database connection drops halfway, orphaned leads exist without events or notifications.

Areas for Improvement:

- Image Asset Hosting: High reliance on external Pexels CDN image URLs without domain optimization in `next.config.ts`. If Pexels throttles or removes photos, broken images appear on the homepage.
